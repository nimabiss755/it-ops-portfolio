# Hosts 管理工具 v3.1

PowerShell + WinForms 写的 hosts 图形编辑器，给不熟悉命令行的同事和一线运维使用。

## 背景：前两版为什么会保存失败

| 现象 | 根因 |
|---|---|
| 对路径 `...\drivers\etc\hosts` 的访问被拒绝 | 保存动作在非管理员进程里执行；或者 hosts 带**只读属性**（即使是管理员，带写权限的打开也会被拒绝） |
| 未能找到文件 `...\hosts` | 提权后的新进程在异常上下文中重新解析路径；32 位进程会被重定向到 SysWOW64 |

在一台出问题的域内机器上用诊断模式采集到 `hosts 属性 = ReadOnly, Archive`，再在开发机上复现，报错文字完全一致，确认了只读属性是其中一个根因。

## v3.1 的做法

- **读写分离**：主界面普通权限就能打开和读取，只在保存时弹一次 UAC，由独立的提权子进程写入，结果（成功/失败、写入身份、进程位数）回传给主界面
- **只读属性处理**：临时清除只读 → 写入 → 回读校验 → 恢复只读，不改动 ACL
- **安全保障**：写前自动备份到 `%LOCALAPPDATA%\HostsEditor\Backups`；写后回读校验，不一致直接报错，不会"假装成功"；保存前检查文件是否被其他程序改过，避免覆盖
- **路径统一解析**：32 位进程走 `Sysnative`，交给 64 位子进程时换回 `System32`
- **格式**：校验行格式（IP + 域名），换行统一 CRLF，保留原编码（UTF-8 / BOM / UTF-16 / ANSI）
- **可诊断**：`-SelfTest` 模式生成诊断报告（只读属性、写权限、ACL、文件占用、提权子进程状态），日志写到 `%LOCALAPPDATA%\HostsEditor\editor.log`

## 使用

1. 双击 `启动Hosts工具.cmd`（不要直接双击 .ps1，会被执行策略拦截）
2. 修改后点「保存并备份」，在 UAC 中点「是」
3. 出问题时双击 `诊断.cmd`，会自动提权并生成 `诊断报告.txt`

## 已知限制

如果诊断显示「管理员权限：True」「只读属性：False」，但仍然「写权限：不能写入」，通常是终端安全软件的 hosts 保护或系统加固策略在拦截。这时需要安全管理员放行，或改用安全软件自带的 hosts 管理功能。
