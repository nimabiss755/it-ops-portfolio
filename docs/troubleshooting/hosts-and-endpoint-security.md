# Hosts 与终端安全

## hosts 写入失败的三种原因

| 诊断结果 | 原因 | 处理 |
|---|---|---|
| 管理员权限：False | 保存进程未提权 | 提权后写入，或只在写入时启动提权子进程 |
| 管理员权限：True，只读属性：True | 文件只读属性会拒绝带写权限的打开，与 ACL 无关 | 临时清除只读 → 写入 → 回读校验 → 恢复只读 |
| 管理员权限：True，只读属性：False，仍不能写入 | 终端安全软件的 hosts 保护或系统加固策略（文件过滤驱动拦截） | 安全管理员放行，或使用安全软件自带的 hosts 管理功能 |

## 两个容易误判的点

- **"未能找到文件"不一定是文件不存在**：32 位进程访问 `System32` 会被重定向到 `SysWOW64`。如果 `Test-Path` 或注册表显示文件存在，但运行时报找不到，先采集实际异常、进程是否提权、进程位数，再决定改不改逻辑。
- **文件过滤驱动**：用 `fltmc filters` 查看已加载的过滤驱动，可以快速判断是否有安全软件在拦截文件写入。
