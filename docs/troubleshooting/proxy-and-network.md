# 企业代理与网络

## 怎样判断流量到底有没有走代理

企业环境里同时存在系统代理、WinHTTP 代理、TUN 虚拟网卡、上网行为管理和终端安全软件，"切换节点后能打开网页"或"代理返回了 HTTP 响应"都**不能证明**目标程序的流量走了代理。

按顺序取证：

1. **看目标程序的真实报错**：区分 DNS 失败、TCP 连接失败、TLS 失败、远端 API 业务报错
2. **看两套代理配置**：浏览器和大多数程序用 WinINet（系统代理）；系统服务和部分 CLI 用 WinHTTP（`netsh winhttp show proxy`），两者可能不一致
3. **看 TUN 是否接管路由**：`route print` 查看默认路由走的是哪张网卡
4. **看进程的实际连接**：`Get-NetTCPConnection -OwningProcess <PID>` 或 `netstat -ano`。连接长期停在 `SYN_SENT` 表示握手发出后没有回应，通常是被策略拦截或路由不通
5. **考虑安全设备**：终端安全软件和上网行为管理可能在本机或出口层面重置连接

结论只基于第 4 步的实际连接证据，不基于"看起来能用"。
