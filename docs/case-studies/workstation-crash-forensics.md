# 案例：工作站蓝屏 / 死机远程取证

## 场景

商用工作站和台式机（HP、Dell）出现反复蓝屏、无响应死机、意外重启。故障机在用户手里，运维人员不在现场，故障也不一定能当场复现。

## 方法

1. **交付自包含脚本**：一个无参数的 PowerShell 脚本（时间窗可配置），用户或现场同事以管理员身份运行
2. **一键采集，按编号输出**，结果打包回传后分析：

| 编号 | 采集内容 | 用途 |
|---|---|---|
| 0 | 机型、BIOS、内存条、系统信息 | 对照厂商已知问题和 BIOS 版本 |
| 1 | Kernel-Power 关机链路事件 | 区分正常关机、断电、强制重启 |
| 2 | WHEA 硬件错误 | 判断是否是 CPU、内存、PCIe 硬件层错误 |
| 3 | 显示驱动 TDR 事件 | 判断是否是显卡驱动超时导致的"假死" |
| 4 | BugCheck 记录 | 蓝屏停止码 |
| 5 | 时间窗内的系统错误 | 找故障前后的关联事件 |
| 6 | 转储文件与转储配置 | 确认 Minidump / MEMORY.DMP 是否生成，转储配置是否正确 |
| 7 | 设备与驱动清单、文件系统筛选驱动 | 排查第三方驱动和安全软件驱动 |
| 9 | 文件清单 | 核对采集完整性 |

3. **主动提示隐私**：输出中说明日志和转储可能包含电脑名、账户、路径，分享前需检查
4. **区分结论等级**：报告里分开写「已确认」「候选原因」「需要进一步证据」。例如 Dell 开机前硬件自检结果不一定写入 Windows 日志，需要另外记录 F12 诊断码

## 价值

- 不依赖现场人员的描述，第一次采集就拿到完整证据
- 同一套采集结构可以对比多次故障（如两个日期的事件对比），判断是否为同一根因

> 采集脚本见 [tools/bsod-collector](../../tools/bsod-collector/)。
